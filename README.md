# InVision U — интеллектуальная система поддержки отбора кандидатов

> **Хакатон**: Decentrathon 5.0 | **Трек**: AI inDrive | **Команда**: BLUE NODE

***

## 1. Проблема

InVision U — инновационный университет со 100% стипендиями от inDrive, запущенный в Казахстане для подготовки будущих лидеров, предпринимателей и основателей проектов.  При приёме абитуриентов приёмная комиссия сталкивается с важными вызовами. 

| Проблема | Последствие |
|----------|-------------|
| Талантливые абитуриенты не умеют «продавать себя» | Система видит **заявку**, а не **человека**  |
| Стандартные формы не выявляют ранние сигналы лидерского потенциала | Сильные кандидаты **самоотсеиваются** ещё до подачи заявки  |
| Генеративный ИИ размывает аутентичность мотивационных эссе | Традиционные текстовые форматы становятся **ненадёжными**  |
| Качество ручного отбора падает при росте количества заявок | Масштаб и глубина оценки становятся **несовместимы**  |

***

## 2. Наше решение

Многоэтапная AI‑платформа оценки кандидатов, которая выходит за рамки классического просмотра анкет. 

```
Путь кандидата:
/apply ──> Заполнение формы ──> AI Nudge‑ассистент ──> SJT‑тест ──> AI‑анализ ──> Просмотр админом
```

### Ключевая инновация: трёхслойная оценка

| Слой | Что это | Зачем |
|------|---------|-------|
| **AI Nudge Assistant** | Генерирует персонализированные вопросы на основе черновика заявки и помогает раскрыть реальный потенциал кандидата | Решает проблему «не умеют себя продавать» — ИИ «вытягивает» настоящего человека  |
| **Situational Judgement Test (SJT)** | 4 реальные сценария, оценивающие решения кандидата по 5 поведенческим осям | Фиксирует лидерские сигналы, которые не видны в эссе, и устойчив к полностью сгенерированным текстам  |
| **Эссе‑анализ по 6 измерениям** | LLM оценивает мотивацию, лидерство, устойчивость, креативность, технический потенциал и социальное влияние | Даёт глубокую оценку с объяснениями и флагом использования ИИ в тексте  |

### Как это закрывает запросы inVision U

| Направление из TOR | Как мы реализуем |
|--------------------|------------------|
| **Идентификация лидерского потенциала** | SJT‑тест + измерение «Лидерство» в анализе эссе  |
| **Оценка “пройденного пути”** | Измерение «Устойчивость» оценивает траекторию роста, а не только достижения; учитывается «rural‑бонус» для контекста  |
| **Детекция генеративного ИИ** | Флаг `is_ai_generated` с вероятностной оценкой в анализе эссе  |
| **Предиктивная аналитика / lead scoring** | Композитный балл, объединяющий оценку эссе ИИ + SJT + баллы за достижения  |
| **Мультимодальная оценка** | Структурированные данные + эссе + SJT‑ответы + диалог с Nudge‑ассистентом  |

## 4. AI‑пайплайн

### 4.1 Essay Analyzer (`server/ai/essayAnalyzer.ts`)

Использует **Groq API** и модель **LLaMA 3.3 70B Versatile**. 

**Вход**: текст эссе, имя кандидата, достижения, университет, город. 

**Выход** (структурированный JSON):

```json
{
  "scores": {
    "motivation":         { "score": 0-100, "confidence": 0.0-1.0, "evidence": "..." },
    "leadership":         { "score": 0-100, "confidence": 0.0-1.0, "evidence": "..." },
    "technicalPotential": { "score": 0-100, "confidence": 0.0-1.0, "evidence": "..." },
    "creativity":         { "score": 0-100, "confidence": 0.0-1.0, "evidence": "..." },
    "resilience":         { "score": 0-100, "confidence": 0.0-1.0, "evidence": "..." },
    "socialImpact":       { "score": 0-100, "confidence": 0.0-1.0, "evidence": "..." }
  },
  "flags": {
    "is_ai_generated": true,
    "generic_content": false,
    "high_potential_outlier": false
  },
  "summary": "Краткая экспертная оценка для членов комиссии"
}
```



**6 измерений оценки**:

| Измерение | Что измеряет | Почему важно для InVision U |
|-----------|--------------|-----------------------------|
| Motivation | Искреннее желание учиться и развиваться | Ключевой предиктор успеха студента  |
| Leadership | Инициативность, влияние, готовность брать ответственность | Миссия inVision U — выращивать лидеров  |
| Technical Potential | Аналитическое мышление и способность решать проблемы | Основа для предпринимательства и построения проектов  |
| Creativity | Оригинальность мышления, нестандартные подходы | Потенциал к инновациям  |
| Resilience | Умение преодолевать трудности, «пройденный путь» | Позволяет заметить «бриллиантов в грязи»  |
| Social Impact | Желание приносить пользу обществу и сообществам | Созвучно социальной миссии inDrive  |

### 4.2 SJT Analyzer (`server/ai/sjtAnalyzer.ts`)

4 ситуационных сценария на русском языке в казахстанском контексте: 

1. Кризис лидерства — конфликт в команде на фоне дедлайна.   
2. Этическая дилемма — обнаружение плагиата перед презентацией.   
3. Ограниченные ресурсы — создание MVP для сельской школы без бюджета.   
4. Восстановление после провала — неудачный демо‑день стартапа.   

Оценка по 5 поведенческим осям: лидерство, решение проблем, командная работа, стрессоустойчивость, этика.   
Выход: обратная связь по каждой ситуации, общий поведенческий профиль и краткое описание личности. 

### 4.3 AI Nudge Assistant (`server/ai/nudgeAnalyzer.ts`)

Анализирует черновик заявки и генерирует **3–5 персонализированных вопросов**, которые помогают раскрыть скрытый потенциал кандидата.  Кандидат отвечает прямо в форме, ответы сохраняются вместе с заявкой. 

**Пример**: кандидат указал участие в олимпиаде без деталей — ассистент спрашивает: «Какова была ваша конкретная роль и что вы из этого вынесли?»   
Так мы закрываем TOR‑проблему: *«Талантливые абитуриенты, не умеющие “продавать себя”, теряются.»* 

### 4.4 Achievement Scorer (`server/ai/achievementScorer.ts`)

Детерминированная прозрачная система подсчёта достижений. 

| Тип достижения | Баллы |
|----------------|-------|
| Олимпиада (национальная) | 20 |
| Олимпиада (региональная) | 12 |
| Олимпиада (городская) | 8 |
| Волонтёрство | 5 в год (макс. 20) |
| Проект (опубликованный/с наградой) | 15 |
| Проект (обычный) | 10 |
| Награда | 8 |



### 4.5 Composite Score (`server/ai/compositeScorer.ts`)

```text
compositeScore = (weightedAiAverage * scaleFactor) + achievementBonus + ruralBonus
```

- **weightedAiAverage** — взвешенное среднее по 6 измерениям ИИ‑оценки, веса настраиваются админами.   
- **achievementBonus** — детерминированные баллы за достижения (с потолком).   
- **ruralBonus** — корректировка для кандидатов из недопредставленных регионов (по умолчанию +5 баллов).   

Все веса настраиваются приёмной комиссией через страницу Settings — человек контролирует формулу.

## 6. Честность и объяснимость

### Human‑in‑the‑Loop

ИИ **никогда** не принимает финальное решение об зачислении. 

1. Система генерирует баллы и рекомендации.   
2. Показывает обоснования и цитаты.   
3. Приёмная комиссия принимает решение.   
4. Все действия фиксируются в аудит‑логе. 

### Снижение предвзятости

- **Rural‑бонус**: допбаллы для абитуриентов из недопредставленных регионов (Кызылорда, Атырау, Актау, Туркестан и др.).   
- Измерение **«Resilience»**: фокус на «пройденном пути», а не только на ресурсах и бэкграунде.   
- Анти‑дискриминационный промпт: ИИ явно запрещено использовать пол, этничность и уровень дохода как негативные факторы.   
- Настраиваемые веса: комиссия может подчеркнуть важные для себя оси (например, усилить устойчивость и социальное влияние). 

### Прозрачность

- Каждому AI‑баллу сопоставлен уровень **уверенности** и **цитаты** из эссе.   
- Формула расчёта композитного балла полностью видна и редактируема.   
- Аудит‑лог фиксирует каждое изменение.   
- Кандидаты видят свою AI‑оценку в личном кабинете.

## 8. Быстрый старт

### Предварительные требования

- **Node.js** 18+  
- **Docker** и Docker Compose  
- **Groq API key** (можно получить бесплатно на console.groq.com) 

### Установка

```bash
# 1. Клонировать репозиторий
git clone https://github.com/Mountygoi/InVision-U.git
cd InVision-U

# 2. Запустить PostgreSQL через Docker
docker compose up -d

# 3. Настроить и запустить сервер
cd server
npm install
# Создать .env с: GROQ_API_KEY=your_key_here
npm run dev
# Сервер: http://localhost:5000

# 4. Настроить и запустить клиент (новый терминал)
cd client
npm install
npm run dev
# Клиент: http://localhost:5173
```



### Переменные окружения (`server/.env`)

## 10. Сценарии использования

### Сценарий 1: Кандидат подаёт заявку

1. Кандидат открывает `/apply` и заполняет личные данные, достижения, навыки.   
2. Пишет эссе или загружает PDF.   
3. Нажимает **«Получить AI‑обратную связь»** — Nudge‑ассистент генерирует вопросы.   
4. Опционально отвечает, ответы сохраняются в заявке.   
5. Нажимает **«Далее: ситуационный тест»**, заявка пишется в БД.   
6. Проходит 4 SJT‑сценария, поясняя свои решения.   
7. Нажимает **«Отправить»** — запускается AI‑пайплайн: SJT‑анализ, эссе‑анализ, расчёт композитного балла.   
8. Получает временный пароль и попадает в личный кабинет статуса. 

### Сценарий 2: Комиссия смотрит кандидатуру

1. Открывает `/admin` и видит дашборд: количество заявок, распределение баллов, разрез по регионам.   
2. Заходит в `/admin/candidates` — видит ранжированный список по композитному баллу.   
3. Фильтрует по статусу/региону/поиску.   
4. Открывает кандидата — видит AI‑резюме, радиальную диаграмму 6 измерений, AI‑флаги, цитаты из эссе и список достижений.   
5. Меняет статус: new → under_review → interview → accepted/declined.   
6. Все действия попадают в аудит‑лог. 

### Сценарий 3: Админ настраивает веса

1. Открывает `/admin/settings`.   
2. Корректирует веса измерений (например, повышает вес «Resilience» для набора с фокусом на регионы).   
3. Сохраняет, система пересчитывает композитные баллы в реальном времени.   
4. Возвращается к списку кандидатов и видит обновлённый рейтинг.

## 11. Ограничения и известные проблемы

- **Нестабильность LLM**: одно и то же эссе может получить немного разные баллы при повторном анализе (частично решено кэшированием результатов).   
- **Язык**: промпты сейчас на русском, эссе на казахском могут получать чуть более низкие оценки.   
- **PDF‑парсинг**: сложные макеты PDF могут некорректно извлекаться.   
- **Нет реального датасета**: демо работает на сидах, полноценная валидация требует настоящих размеченных данных приёмной кампании.   
- **Пароли**: пока хранятся в открытом виде (только для прототипа; в проде нужен bcrypt).   
- **Нет rate limiting**: API без ограничений по запросам (в продакшене нужен express-rate-limit).   
- **Один LLM‑провайдер**: сейчас только Groq/LLaMA, в проде логично перейти к ансамблю моделей.
